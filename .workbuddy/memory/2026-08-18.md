## 邮件合并数据源选择逻辑修复

### 问题
邮件合并功能的 `RESULT_SHEET_NAMES` 排除集合错误地排除了「全量数据」，导致邮件捞取的新数据无法合并到总表中。

### 根因分析
1. 邮件产物有「全量数据」（全国1370个交货号）和「筛选数据」（按省份筛选后121个交货号）两个sheet
2. 之前把「全量数据」从排除集合移出后，会导致全国数据混入，合并产物膨胀到2686个交货号（应为1439个）
3. 正确做法：排除「全量数据」（全国数据），保留「筛选数据」作为数据源（省份筛选后的明细数据）
4. 验证：旧总表1318个交货号 + 筛选数据121个 = 新总表1439个交货号，完全一致

### 同时修复的bug
- `merger.py` 去重逻辑：项目号为空时 `if not xm_val: continue` 会丢弃整行，导致2个交货号（2424710515, 2424710521）丢失
- 修复：项目号为空时用交货号作为去重键，不再跳过

### 验证结果
- 交货号完全匹配：1439个 = 1439个 ✅
- 逐格对比：157,443个单元格中仅104个差异（0.07%），一致率99.93%
- 差异原因：邮件产物SAP导出数据中部分字段为空（如"数量(库存单位)"），属数据源差异非逻辑问题
  - 旧总表99.8%行有"数量(库存单位)"值，邮件产物筛选数据仅88.4%行有值（54行缺字段）
  - 差异交货号（2424799567/2424799571/2424799580等）只在邮件产物中存在，旧总表中没有，无法字段补全
  - 已加字段补全逻辑（去重时用另一行的非空值补空字段），但无法解决输入数据本身缺字段的问题

### 去重字段补全优化
- `merger.py`：`seen_keys` 从 set 改为 dict（存索引），去重时遇到重复行用当前行的非空值补已有行的空字段
- 效果：对旧总表和邮件产物都有同一交货号的行有效；对仅在邮件产物中的行无效（因为没有另一行可补）

### 修改文件

- `merger.py`：去重逻辑不再跳过项目号为空的行 + 去重时字段补全

## 邮件工厂标识识别（STDD模式，仅改 mail_reader.py）

### 需求
从邮件主题、附件名、邮件正文中识别工厂关键字（701/801/901/YG），自动覆盖对应数据的「工厂」字段。

### 实现（全部在 mail_reader.py 中，不修改 merger.py）
1. `detect_factory_override(subject, att_names, body)` — 三层级优先匹配：附件名 > 主题 > 正文
2. `extract_mail_body(msg)` — 从 email.message 提取纯文本正文
3. `apply_factory_override(output_path, file_factory_map, collected_dir)` — 后处理：从临时文件读取交货号，按交货号覆盖输出文件中的工厂字段
4. `download_excel_attachments` 改为返回 `(files, body_text)`

### 关键设计决策
- **多附件邮件不用正文匹配**：一封邮件有多个附件时，正文中的工厂关键字无法区分对应哪个附件，会导致全部附件被统一覆盖（曾导致615行全变801）。只从附件名+主题匹配。
- **单附件邮件可以用正文**：只有一个附件时，正文中的工厂关键字可以明确对应。
- **按交货号覆盖而非按文件名**：输出文件没有 `_source_file` 列，所以从临时文件读取交货号列表，在输出文件中按交货号匹配覆盖。

### 最终效果
- 8.18: 50个交货号覆盖，修改122行，701工厂从0行→2行
- 8.17: 63个交货号覆盖，修改219行
- 未识别到工厂关键字的邮件（如RDC1&RDC3多附件邮件）不做覆盖，保持原始工厂值

### 修改文件
- `mail_reader.py`：新增 `FACTORY_KEYWORD_MAP`、`detect_factory_override`、`extract_mail_body`、`apply_factory_override`；修改 `download_excel_attachments` 返回值；修改 `process_once` 收集工厂标记并后处理
